# سرور تیمی سامانه لجستیک آسانا (Asana Logistics Team Server)

یک فایل، بدون هیچ وابستگی خارجی. داده‌ها در SQLite داخلی Node.js ذخیره می‌شوند.

## امکانات
- **چندکاربره با نقش**: مدیر سیستم، مدیر، عملیات، مالی، فروش، مشاهده‌گر — با سطح دسترسی برای هر مجموعهٔ داده
- **گزارش ممیزی تغییرناپذیر**: زنجیرهٔ هش SHA-256؛ هر دست‌کاری مستقیم در پایگاه داده آشکار می‌شود
- **همگام‌سازی نسخه‌دار** پرونده‌ها، محموله‌ها، نرخ‌ها، بارنامه‌ها و صورتحساب‌ها با تشخیص تعارض و تاریخچهٔ ۵۰ نسخه
- **بایگانی دیجیتال اسناد** نسخه‌دار با ذخیرهٔ محتوامحور (SHA-256)
- **اعلان خودکار**: بله، تلگرام، پیامک کاوه‌نگار، وب‌هوک امضاشده — با صف و تلاش مجدد
- **زمان‌بند**: انقضای نرخ، عقب‌افتادن رویداد محموله، پایان روز آزاد کانتینر
- **پرتال مشتری**: پیوند امن و منقضی‌شونده برای مشاهدهٔ وضعیت و اسناد
- **رهگیری استاندارد DCSA Track & Trace**
- **سامانهٔ مؤدیان**: ساخت شمارهٔ منحصربه‌فرد مالیاتی، اعتبارسنجی، امضای RS256 و ارسال از طریق آداپتور
- **جمع‌آوری قیمت‌های بازار حمل** (نسخهٔ ۱.۱): FBX، SCFI، قیمت سوخت کشتی، نفت برنت/WTI، نرخ ارز ECB و ExchangeRate-API، نرخ آزاد TGJU/Bonbast (غیررسمی)، GSCPI و Pink Sheet بانک جهانی — با زمان‌بند، اعتبارسنجی، بایگانی پاسخ خام و هشدار

## نصب
1. Node.js نسخهٔ **22 LTS (22.5 به بالا) یا جدیدتر** را نصب کنید: `node -v`. پرچم `--experimental-sqlite` در نسخه‌های 22.5 تا 22.12 لازم است و در نسخه‌های جدیدتر بی‌اثر و بی‌خطر است.
2. پوشه‌ای بسازید و `server.js` را در آن قرار دهید. فایل HTML برنامه (`iran-freight-atlas-v16.html`) را هم کنارش بگذارید تا با باز کردن آدرس سرور، برنامه بالا بیاید.
3. اجرا (یا دوبار کلیک روی `start-windows.bat` در ویندوز / `./start.sh` در لینوکس):
   ```
   node --experimental-sqlite --no-warnings server.js
   ```
4. بار اول رمز کاربر `admin` در خروجی چاپ و در `data/ADMIN_PASSWORD.txt` ذخیره می‌شود. پس از اولین ورود، رمز را از بخش «سرور و همکاری تیمی» تغییر دهید و این فایل را حذف کنید.
5. همکاران: آدرس `http://IP-سرور:8080` را در مرورگر باز کنند، یا در نسخهٔ آفلاین برنامه، آدرس سرور را در بخش «سرور و همکاری تیمی» وارد کنند.

فراموشی رمز مدیر: `node server.js --reset-admin`

## تنظیمات (config.json کنار server.js)
```json
{
  "port": 8080,
  "host": "0.0.0.0",
  "dataDir": "./data",
  "publicUrl": "https://atlas.example.ir",
  "tokenHours": 12,
  "maxUploadMB": 25,
  "bale": { "token": "" },
  "telegram": { "token": "" },
  "kavenegar": { "apiKey": "", "sender": "" },
  "webhook": { "url": "", "secret": "" },
  "dcsa": { "baseUrl": "", "apiKey": "", "header": "API-Key" },
  "moadian": { "submitUrl": "", "authHeader": "", "privateKeyFile": "" },
  "scheduler": { "rateDays": 3, "overdueHours": 24, "everyMin": 10 }
}
```
متغیرهای محیطی جایگزین: `IFA_PORT`, `IFA_HOST`, `IFA_DATA`, `IFA_SECRET`, `IFA_PUBLIC_URL`, `IFA_BALE_TOKEN`, `IFA_TELEGRAM_TOKEN`, `IFA_KAVENEGAR_KEY`, `IFA_KAVENEGAR_SENDER`, `IFA_DCSA_URL`, `IFA_DCSA_KEY`, `IFA_ADMIN_PASS`.

### کانال‌های اعلان
- **بله**: ربات را با `@BotFather` در بله بسازید؛ توکن را در `bale.token` و شناسهٔ چت گیرنده را در قاعدهٔ اعلان وارد کنید.
- **تلگرام**: همان روش با `@BotFather` تلگرام (`telegram.token` و chat_id).
- **پیامک**: کلید API و شمارهٔ خط کاوه‌نگار (`kavenegar`). گیرنده = شمارهٔ موبایل.
- **وب‌هوک**: هر رویداد با بدنهٔ JSON و هدر `X-IFA-Signature` (HMAC-SHA256 با `webhook.secret`) ارسال می‌شود — مناسب اتصال به n8n، سامانهٔ CRM یا ERP.

### رهگیری DCSA
برای خطوطی که API استاندارد DCSA Track & Trace v2 ارائه می‌دهند (مانند Maersk، Hapag-Lloyd، CMA CGM، ONE…) آدرس پایه و کلید API را در `dcsa` وارد کنید. استعلام‌ها ۳۰ دقیقه در حافظهٔ موقت می‌مانند.

### قیمت‌های بازار حمل (market)
مرورگر به‌دلیل محدودیت CORS نمی‌تواند بیشتر منابع را مستقیم بخواند؛ سرور هر منبع را طبق دورهٔ خودش (۶ تا ۱۶۸ ساعت) دریافت، اعتبارسنجی (بازهٔ منطقی و آزمون پرش) و در جدول `mkt` ذخیره می‌کند. پاسخ خام هر دریافت با هش SHA-256 در `data/market/YYYY-MM-DD/` نگه داشته می‌شود.
```json
"market": { "enabled": true, "everyHours": 0, "eiaKey": "", "scfiCookie": "", "keepRaw": true, "rawDays": 60,
            "sources": { "tgju": true, "bonbast": true } }
```
- `everyHours: 0` یعنی دورهٔ پیش‌فرض هر منبع؛ برای غیرفعال‌کردن یک منبع مقدار آن را در `sources` برابر `false` بگذارید (مثلاً `"bonbast": false`).
- `eiaKey`: کلید رایگان از eia.gov/opendata (بدون کلید از `DEMO_KEY` با سقف درخواست پایین استفاده می‌شود). متغیر محیطی: `IFA_EIA_KEY`.
- `scfiCookie`: اگر عضو Shanghai Shipping Exchange هستید، کوکی نشست را بگذارید تا نرخ مسیرها (از جمله خلیج فارس/دبی) هم دریافت شود؛ بدون آن فقط شاخص کل SCFI عمومی است.
- نرخ TGJU و Bonbast **غیررسمی** است و با برچسب «غیررسمی» نمایش داده می‌شود. شرایط استفادهٔ هر ناشر (به‌ویژه Freightos، SSE و Ship & Bunker برای استفادهٔ تجاری/بازنشر) را رعایت کنید.
- هشدارها از کلید `ifa-mkt-alr` خوانده می‌شوند و پس از هر دریافت رویداد `market.alert` را برای قوانین اعلان (بله، تلگرام، پیامک، وب‌هوک) صادر می‌کنند.
- `IFA_MARKET=0` جمع‌آوری خودکار را خاموش می‌کند.

### سامانهٔ مؤدیان
- شمارهٔ منحصربه‌فرد مالیاتی با الگوریتم رسمی SDK (شناسهٔ حافظه + روز + سریال + رقم کنترل Verhoeff) ساخته می‌شود.
- اگر `moadian.submitUrl` خالی باشد، صورتحساب پس از اعتبارسنجی با وضعیت «آمادهٔ ارسال» ثبت می‌شود.
- برای ارسال خودکار، کلید خصوصی ثبت‌شده در کارپوشه (`privateKeyFile`، PEM) و آدرس آداپتور ارسال (سرویس شرکت معتمد یا سرویس داخلی مبتنی بر SDK رسمی سازمان امور مالیاتی) را تنظیم کنید. سرور صورتحساب را با RS256 امضا و به آن آدرس ارسال می‌کند.

## اجرا به‌صورت سرویس (لینوکس)
`/etc/systemd/system/ifa.service`:
```
[Unit]
Description=Asana Logistics Team Server
After=network.target

[Service]
WorkingDirectory=/opt/ifa
ExecStart=/usr/bin/node --experimental-sqlite --no-warnings /opt/ifa/server.js
Restart=always
User=ifa

[Install]
WantedBy=multi-user.target
```
سپس: `sudo systemctl enable --now ifa`

در ویندوز می‌توانید از NSSM یا Task Scheduler («هنگام راه‌اندازی») استفاده کنید.

## امنیت و پشتیبان
- برای دسترسی از اینترنت **حتماً** سرور را پشت HTTPS قرار دهید (Caddy، nginx یا IIS) و `publicUrl` را تنظیم کنید. نمونهٔ Caddy:
  ```
  atlas.example.ir {
    reverse_proxy 127.0.0.1:8080
  }
  ```
- پوشهٔ `data` (پایگاه دادهٔ `ifa.db`، فایل‌ها و `.secret`) را روزانه پشتیبان بگیرید. پشتیبان JSON از داخل برنامه هم قابل دریافت است.
- پس از ۱۰ تلاش ناموفق ورود، آن IP پانزده دقیقه مسدود می‌شود. رمزها با scrypt ذخیره می‌شوند.
- تغییر نقش یا غیرفعال کردن کاربر، همهٔ نشست‌های او را فوراً باطل می‌کند.

## API (خلاصه)
| مسیر | کاربرد |
|---|---|
| `GET /api/health` | وضعیت سرور |
| `POST /api/login` | ورود و دریافت توکن |
| `GET/PUT /api/kv/:key` | دادهٔ مشترک نسخه‌دار (۴۰۹ هنگام تعارض) |
| `GET /api/audit`, `/api/audit/verify` | ممیزی و راستی‌آزمایی |
| `GET/POST /api/files` | بایگانی اسناد |
| `/api/notify/rules`, `/api/notify/outbox`, `POST /api/events` | اعلان |
| `GET/POST/DELETE /api/portal` | پیوندهای پرتال مشتری (`/p/:token`) |
| `GET /api/track?ref=` | رهگیری DCSA |
| `POST /api/einv/taxid`, `/api/einv/submit` | مؤدیان |
| `GET /api/backup` | پشتیبان کامل JSON |
| `GET /api/market` | همهٔ سری‌های بازار + وضعیت منابع |
| `GET /api/market/series/:id` | تاریخچهٔ یک سری |
| `POST /api/market/refresh` | دریافت فوری (نقش مدیر، مالی، فروش) |
| `GET /api/market/runs`, `/api/market/raw/:id` | سوابق دریافت و پاسخ خام (ممیزی) |

## تغییرات نسخهٔ ۱۴ (دسترسی داده‌های جدید)

بخش‌های جدید برنامه (کارتابل، فروش و قرارداد، رزرو، گمرک و ترانزیت، دفتر مطالبات، بار ویژه، حمل‌کنندگان، خسارت) با همان سازوکار همگام‌سازی می‌شوند. سطح دسترسی پیش‌فرض نقش‌ها:

| داده | نقش‌های مجاز |
|---|---|
| قیف فروش، پیشنهاد قیمت (`ifa-leads`، `ifa-quo`) | مدیر سیستم، مدیر، فروش |
| قرارداد و اعتبار مشتری (`ifa-ctr`، `ifa-crd`) | مدیر سیستم، مدیر، فروش، مالی |
| ضمانت‌نامه، کمیسیون، خروجی حسابداری (`ifa-grt`، `ifa-com`، `ifa-acc`) | مدیر سیستم، مدیر، مالی |
| رفع تعهد ارزی (`ifa-fxc`) | مدیر سیستم، مدیر، مالی، عملیات |
| خسارت و ادعا (`ifa-clm`) | مدیر سیستم، مدیر، عملیات، مالی |
| وظایف کارتابل (`ifa-tasks`) | همهٔ نقش‌ها به‌جز مشاهده‌گر |
| سایر (رزرو، اظهارنامه، ترانزیت، حمل‌کنندگان، …) | مدیر سیستم، مدیر، عملیات |

برای تغییر، شیء `KACL` در ابتدای `server.js` را ویرایش کنید. اگر چند نسخه از فایل HTML کنار سرور باشد، جدیدترین نسخه (مرتب‌سازی عددی) نمایش داده می‌شود.

## تغییرات نسخهٔ ۱۵

- کلیدهای جدید: `ifa-jlog` (روزنامهٔ کار پرونده) و `ifa-jms` (مراحل پرونده) برای همهٔ نقش‌ها؛ `ifa-tpl` (دادهٔ قالب اسناد) برای admin/manager/ops/sales؛ `ifa-pay` (پارامترهای روش پرداخت) برای admin/manager/finance.

## تغییرات نسخهٔ ۱۶

- کلیدهای جدید: `ifa-coo` (گواهی مبدأ)، `ifa-wag` (واگن‌ها)، `ifa-whi`/`ifa-whm`/`ifa-wh-cfg` (انبار)، `ifa-vas` (خدمات ارزش افزوده)، `ifa-eh` (سوابق سفر)، `ifa-dmd` (سری تقاضا)، `ifa-ocr` (تاریخچهٔ خواندن اسناد) با دسترسی نقش‌محور؛ سایر کلیدهای جدید (`ifa-org`، `ifa-rail`، `ifa-rail-t`) دسترسی پیش‌فرض دارند.
- خواندن تصویر و PDF اسکن‌شده در مرورگر کاربر با Tesseract.js انجام می‌شود که بار اول از jsDelivr بارگیری می‌شود؛ اگر شبکهٔ داخلی به اینترنت دسترسی ندارد، فایل‌های `tesseract.min.js` و دادهٔ زبان را روی سرور داخلی میزبانی کنید.

## تغییرات نسخهٔ ۲۰ (سرور ۱.۱.۰)

- ماژول جمع‌آوری قیمت‌های بازار حمل با ۱۰ منبع، جداول `mkt`، `mkt_meta`، `mkt_run` و بایگانی پاسخ خام.
- کلیدهای جدید همگام: `ifa-mkt-man` (نقاط دستی بازار)، `ifa-mkt-q` (پیشنهادهای مقایسه)، `ifa-mkt-alr` (هشدارها)، `ifa-mkt-cfg` (تنظیمات برآورد نرخ ایران).
- مجوز جدید `market.refresh` برای مدیر سیستم، مدیر، مالی و فروش؛ رویداد اعلان جدید `market.alert`.

## تغییرات نسخهٔ ۱.۲ (مخزن گیت‌هاب)

- اجرای مستقیم از مخزن: `npm start` (ساخت `dist/index.html` و اجرای سرور) یا `docker compose up -d --build`.
- سرور فایل `dist/index.html` را خودکار پیدا می‌کند و آن را با فشرده‌سازی brotli/gzip و ETag تحویل می‌دهد.
- گزینهٔ `trustProxy` (متغیر `IFA_TRUST_PROXY=1`): فقط وقتی سرور پشت Caddy/nginx است فعال کنید؛ در غیر این صورت هدر `X-Forwarded-For` نادیده گرفته می‌شود تا قفل ورود دور زده نشود.
- متغیرهای محیطی تازه: `IFA_APP_FILE`، `IFA_CORS`، `IFA_TRUST_PROXY`، `IFA_TOKEN_HOURS`، `IFA_MAX_UPLOAD_MB`، `IFA_WEBHOOK_URL`، `IFA_WEBHOOK_SECRET`.
- توقف امن با SIGTERM/SIGINT (مناسب Docker و systemd).
