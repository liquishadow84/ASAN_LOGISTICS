# سامانه لجستیک آسانا · Asana Logistics

برنامهٔ وب فارسی (RTL) برای مسیریابی، قیمت‌گذاری و مدیریت عملیات حمل‌ونقل بین‌المللی به/از ایران، به‌همراه **سرور تیمی** برای کار چندکاربره، همگام‌سازی، بایگانی اسناد، اعلان و پرتال مشتری.

این مخزن نسخهٔ اجرایی و قابل استقرارِ برنامهٔ `asana-logistics-v20.html` است — **رابط کاربری دقیقاً همان طراحی اصلی است** و یک اثرانگشت SHA-256 (`app/UI_SHA256`) در هر ساخت و در CI تضمین می‌کند که حتی یک بایت از رابط کاربری تغییر نکرده است.

## امکانات

| بخش | توضیح |
|---|---|
| برنامهٔ وب | نقشه و مسیریابی چندوجهی (دریایی، ریلی، جاده‌ای، هوایی، خزر)، هزینه/زمان/ریسک/CO₂، داشبورد، فروش و قرارداد، عملیات، گمرک و ترانزیت، مالی، اسناد، بازار حمل، … — بدون سرور هم کامل کار می‌کند (ذخیره در `localStorage` و IndexedDB) |
| احراز هویت و نقش‌ها | scrypt، توکن HMAC، قفل پس از ۱۰ تلاش ناموفق، ۶ نقش و ACL برای هر مجموعهٔ داده |
| همگام‌سازی تیمی | نسخه‌دار با تشخیص تعارض (۴۰۹)، ادغام سه‌طرفه، تاریخچه و بازگردانی تا ۵۰ نسخه |
| ممیزی | زنجیرهٔ هش SHA-256 با راستی‌آزمایی و تشخیص دست‌کاری |
| بایگانی اسناد | ذخیرهٔ محتوامحور SHA-256، نسخه‌دار، حذف تکراری |
| اعلان | بله، تلگرام، پیامک کاوه‌نگار، وب‌هوک امضاشده (HMAC) با صف و تلاش مجدد |
| پرتال مشتری | پیوند امن منقضی‌شونده برای وضعیت محموله و اسناد عمومی |
| یکپارچه‌سازی | رهگیری DCSA Track & Trace v2، سامانهٔ مؤدیان (شمارهٔ مالیاتی، اعتبارسنجی، امضای RS256)، جمع‌آوری قیمت‌های بازار (FBX، SCFI، سوخت کشتی، برنت/WTI، ECB، …) |

## راه‌اندازی سریع

### ۱) با Node.js (بدون هیچ وابستگی npm)
پیش‌نیاز: **Node.js ۲۲٫۵ یا جدیدتر** (`node -v`).

```bash
git clone https://github.com/liquishadow84/ASAN_LOGISTICS.git
cd ASAN_LOGISTICS
npm start            # = ساخت dist/index.html + اجرای سرور روی پورت 8080
```
ویندوز: دوبار کلیک روی `start-windows.bat` · لینوکس/مک: `sh start.sh`

سپس `http://localhost:8080` را باز کنید. بار اول رمز کاربر `admin` در خروجی چاپ و در `server/data/ADMIN_PASSWORD.txt` ذخیره می‌شود (یا از پیش با `IFA_ADMIN_PASS` تعیین کنید). در برنامه به بخش **سیستم ← سرور و همکاری تیمی** بروید و وارد شوید؛ پس از اولین ورود رمز را عوض و آن فایل را حذف کنید.

فراموشی رمز مدیر: `npm run reset-admin`

### ۲) با Docker
```bash
cp .env.example .env          # در صورت نیاز ویرایش کنید
docker compose up -d --build  # http://localhost:8080
docker compose logs ifa       # رمز اولیهٔ admin
```
با HTTPS خودکار (Let's Encrypt از طریق Caddy):
```bash
DOMAIN=atlas.example.ir IFA_TRUST_PROXY=1 IFA_PUBLIC_URL=https://atlas.example.ir \
  docker compose --profile https up -d --build
```
داده‌ها در volume `ifa-data` (مسیر `/data` داخل کانتینر) نگهداری می‌شوند.

### ۳) نسخهٔ آفلاین تک‌فایلی
پس از `npm run build`، فایل `dist/index.html` را می‌توان مستقیم در مرورگر باز کرد (بدون سرور). برای همکاری تیمی، آدرس سرور را در بخش «سرور و همکاری تیمی» وارد کنید.

## تنظیمات
فایل `server/config.json` (نمونه: `config.example.json`) یا مسیر دلخواه با `IFA_CONFIG`. متغیرهای محیطی بر فایل مقدم‌اند:

| متغیر | کاربرد |
|---|---|
| `IFA_PORT` / `IFA_HOST` | پورت و آدرس گوش‌دادن (پیش‌فرض `8080` / `0.0.0.0`) |
| `IFA_DATA` | پوشهٔ داده (پایگاه دادهٔ SQLite، اسناد، کلید امضا) |
| `IFA_ADMIN_PASS` | رمز اولیهٔ admin (فقط وقتی پایگاه داده خالی است) |
| `IFA_PUBLIC_URL` | آدرس عمومی HTTPS برای پیوندهای پرتال مشتری |
| `IFA_TRUST_PROXY` | `1` فقط پشت Caddy/nginx؛ در غیر این صورت `X-Forwarded-For` نادیده گرفته می‌شود |
| `IFA_SECRET` | کلید امضای توکن (در صورت خالی بودن، تصادفی ساخته و در `data/.secret` نگهداری می‌شود) |
| `IFA_TOKEN_HOURS` / `IFA_MAX_UPLOAD_MB` / `IFA_CORS` / `IFA_APP_FILE` | مدت نشست، حداکثر حجم سند، CORS، مسیر فایل برنامه |
| `IFA_BALE_TOKEN`، `IFA_TELEGRAM_TOKEN`، `IFA_KAVENEGAR_KEY`، `IFA_KAVENEGAR_SENDER`، `IFA_WEBHOOK_URL`، `IFA_WEBHOOK_SECRET` | کانال‌های اعلان |
| `IFA_DCSA_URL`، `IFA_DCSA_KEY` | رهگیری DCSA |
| `IFA_MARKET=0`، `IFA_EIA_KEY` | خاموش‌کردن جمع‌آوری بازار / کلید EIA |

راهنمای کامل سرور (کانال‌ها، مؤدیان، بازار، API): [`server/README.md`](server/README.md)


## معماری
- **کلاینت**: برنامهٔ تک‌فایلی (React کامپایل‌شده + ماژول‌های استودیو). داده‌ها با کلیدهای `ifa-*` در مرورگر ذخیره می‌شوند؛ با اتصال به سرور، همین کلیدها هر ۳۰ ثانیه با `GET/PUT /api/kv` همگام می‌شوند (کنترل هم‌زمانی خوش‌بینانه با شمارهٔ نسخه).
- **سرور**: یک فایل Node.js با SQLite داخلی (WAL)؛ جداول کاربران، kv و تاریخچه، ممیزی زنجیره‌ای، اسناد، قوانین و صف اعلان، پرتال، مؤدیان، رهگیری و بازار. برنامه را با ETag و فشرده‌سازی brotli/gzip تحویل می‌دهد (≈۹ ← ≈۴٫۵ مگابایت).
- **بدون وابستگی به سرویس ابری خارجی**؛ تنها ارتباطات بیرونی همان منابعی است که خودتان فعال می‌کنید (کانال‌های اعلان، DCSA، منابع بازار) به‌علاوهٔ فونت‌های Google Fonts و Tesseract.js (برای OCR) که برنامهٔ اصلی از CDN بارگیری می‌کند.

## توسعه و آزمون
```bash
npm run build      # ساخت dist/index.html و بررسی اثرانگشت رابط کاربری
npm test           # آزمون‌های API، امنیت و تحویل (بدون وابستگی)
npm install && npx playwright install chromium
npm run test:e2e   # برنامهٔ واقعی در Chromium ↔ سرور واقعی: ورود و همگام‌سازی دوطرفه
```
اگر عمداً رابط کاربری را تغییر دادید: `npm run build -- --update-fingerprint`.

## امنیت و نگهداری
- برای دسترسی از اینترنت حتماً پشت HTTPS (Caddy/nginx) اجرا کنید و `IFA_TRUST_PROXY=1` و `IFA_PUBLIC_URL` را تنظیم کنید.
- از پوشهٔ داده (`ifa.db`، `files/`، `.secret`) روزانه پشتیبان بگیرید؛ پشتیبان JSON از داخل برنامه هم در دسترس است (`GET /api/backup`، فقط مدیر سیستم).
- رمزها با scrypt ذخیره می‌شوند؛ تغییر نقش یا غیرفعال‌کردن کاربر همهٔ نشست‌های او را فوراً باطل می‌کند.

## محدودیت‌ها (شفاف)
- نرخ‌ها و برآوردهای داخلی برنامه — همان‌طور که خود برنامه اعلام می‌کند — تخمینی و نمونه‌اند و جایگزین استعلام رسمی نیستند.
- جمع‌آوری قیمت‌های بازار به ساختار صفحات/API منابع ثالث وابسته است و با تغییر آن‌ها ممکن است خطا دهد (خطا در وضعیت منبع نمایش داده می‌شود). شرایط استفادهٔ هر ناشر را رعایت کنید.
- ارسال واقعی به سامانهٔ مؤدیان نیازمند آداپتور ارسال (`moadian.submitUrl`) و کلید خصوصی ثبت‌شده است؛ رهگیری DCSA نیازمند کلید API خط کشتیرانی است.
